# GRD3 简体中文补丁

这是项目级技能，依赖完整仓库。仓库根目录是本文件所在目录的 `../../..`，其中应存在 `patch_grd3.py`；先定位该目录，再以它为工作目录执行命令。不要只复制这个技能目录到全局技能文件夹。

先读 [README](../../../README.md) 和[恢复边界](../../../docs/recovery.md)。说明证据范围：只有 1 台日版 GRD3 通过基本拍摄、回放和重启检查，未验证故障救砖。按用户已有授权执行，缺什么信息才问什么。

## 只校验已有文件包

如果用户只要求检查一个已生成的包，确认包路径后直接运行下方的 `verify`，无需让用户重新查询机身版本。校验通过只能证明文件与项目固定输出一致，不能证明用户相机的型号、版本或刷写状态。

## 生成前核对

1. 确认实际机身为日版 **GR DIGITAL III（2009）**。用户只说“GR3”时先澄清型号。
2. 收集用户从机身读到的版本：**MAIN 2.50、BKUP 1.00、MONI 1.00、EXTD 1.18、CPU1 1.00**。沿用本次会话已有信息，不用仓库示例补齐未知项。缺项就询问；不匹配则停止生成，按 README 解释当前测试范围。查询方法使用 README 中的官方说明。
3. 确认官方 `gr3-250.zip` 或含 `GLAUNCH3`、`GLAUNCH8` 的原版解压目录在当前执行环境中可读。没有文件时指向 README 的理光官方下载页，让用户阅读条款并获取文件；不使用来源不明的预改固件。
4. 检查 Python 版本至少为 3.10，并选择电脑上尚不存在的输出目录，例如 `build/grd3-zh`。输出目录不能指向相机、存储卡或其挂载点。若已有目录，校验已有包或选新的目录，不删除或覆盖原文件。

这些条件未满足时，可以继续阅读文档或检查环境，但不要生成供该机身使用的包。若助手没有文件或终端权限，明确能力限制并提供命令，不声称已执行。

## 执行本地工具

将占位路径替换成已确认的真实路径并正确引用，不直接把用户文本拼进 shell。以下命令中的 `1.18` 必须来自用户的机身读数；它不是自动检测结果。

macOS / Linux：

```bash
python3 --version
python3 patch_grd3.py build "/path/to/gr3-250.zip" "build/grd3-zh" --extd-version 1.18
python3 patch_grd3.py verify "build/grd3-zh"
```

Windows PowerShell：

```powershell
py -3 --version
py -3 patch_grd3.py build "C:\Downloads\gr3-250.zip" "build\grd3-zh" --extd-version 1.18
py -3 patch_grd3.py verify "build\grd3-zh"
```

逐条检查退出码，`build` 成功后再运行 `verify`。退出码 `0` 表示成功，`1` 表示校验或读写失败，`2` 表示命令参数错误。失败时报告错误原文和失败步骤，不继续准备存储卡。不要通过修改固定哈希、校验算法、版本号或文件头来消除报错。

校验成功后读取输出目录中的 `manifest.json` 和 `SHA256SUMS.txt`。它们给出工具版本、精确四字节改动和文件哈希；`extd_version_manually_confirmed_by_user` 是传入值的记录，不是工具读取机身的证据。
