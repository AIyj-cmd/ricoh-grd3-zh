# 技术说明

本文区分文件分析、电脑验证和本机运行结果。所有地址均针对已知 SHA-256 的 GRD3 MAIN 2.50；不能移用于 GXR 或现代 GR III。

## 最小改动

MAIN 有 512 字节大端头部，程序载入基址为 `0x2004B000`。资源文件名指针表的运行地址是 `0x203A68C4`，对应完整 GLAUNCH3 的文件偏移 `0x35BAC4`。

| 项目 | 原值 | 修改后 |
| --- | --- | --- |
| 日语槽指针 | `0x203A68F0`，指向 `com_main_jpn.res` | `0x203A6956`，指向 `com_main_chinsimpl.res` |
| 第 6 号语言槽（简体中文） | `0x203A6956` | 不变 |
| 英文槽 | 原值 | 不变 |
| 主程序校验值 | `0x785F5592` | `0x785F53C6` |

实际发生变化的字节：

| GLAUNCH3 文件偏移 | 原值 | 新值 |
| --- | --- | --- |
| `0x16E` | `55` | `53` |
| `0x16F` | `92` | `C6` |
| `0x35BAC6` | `68` | `69` |
| `0x35BAC7` | `F0` | `56` |

没有修改代码指令、版本号或 EXTD 内容。语言 ID 仍为 0，因此这一方案并非修改地区参数或完整语言解锁。

## 校验

头部 `0x20` 的大端 u32 决定权重相位；正文是文件 `0x200` 之后的字节。校验值存储在 `0x16C`：

```text
checksum = sum(payload[i] * (((start + i) % 6) + 2)) modulo 2^32
```

工具同时检查完整文件长度、正文长度、型号和结束标识、MAIN 模块类型、载入地址及完整 SHA-256。此 GRD3 文件的两个标识用 **XOR 0x80** 解码，不应套用其他型号的处理规则。

撤销指针修改并重算校验，结果可恢复为完全相同的官方文件。**这是电脑上的字节级可逆性，不是刷坏机身后的恢复试验。**

## 中文资源与字体证据

本机 EXTD 1.18 已提取并通过内部校验。该模块含日语及简体中文资源，按加载器的每个 NUL 分割规则，两者均有 1,277 个条目；日语块 17,861 字节，简体中文块 14,435 字节。

| 代码位置 | 离线分析结果 |
| --- | --- |
| `0x203722AC` | 根据语言槽中的文件名加载资源 |
| `0x20330390` | 初始化字库页索引 |
| `0x20330BC4` | 按文本中的字库页和字形号读取字形 |

离线解码曾正确显示“手动对焦、快拍、无限远”等文字，随后本机实测确认了中文菜单显示。字形页并非照搬 GXR 的按语言字体掩码实现。

本机完整 EXTD 头部＋正文的 SHA-256 为：

```text
49b40de2fa7f0a37325f8618f7a93eb05f768ed4917a33f9ff98e514c40e2c7a
```

这个值仅记录研究输入，不表示工具检查了其他相机的 EXTD。仓库不发布本机资源转储，也不要求使用者运行实验性导出脚本。工具只改官方 MAIN 文件，运行时仍使用各机身已有资源。
