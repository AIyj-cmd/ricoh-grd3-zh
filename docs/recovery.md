# 回退与故障恢复

**目前没有经过本项目实机验证的 GRD3 救砖方法。** `stock/` 中的文件只是原版升级文件。

## 相机仍可正常进入更新界面

理论上可使用未修改的官方 `GLAUNCH3`、`GLAUNCH8` 执行正常更新。工具保留的原版文件有固定哈希，本机也成功接受过相同 2.50 版本的中文更新。

但本项目**没有实测刷回原版**。只有在更新入口仍可工作时，正常回退才具有操作前提；它不能保证修复无法开机的机身。请参照[官方更新说明](https://www.ricoh-imaging.co.jp/english/r_dc/download/firmware/docs/grd3_fwup_en.pdf)，不要为绕过提示擅改版本号。

## 主程序不能运行时

本机 MONI 1.00 的静态分析确认存在独立 MAIN/BKUP 加载路径：

| 地址 | 分析结果 |
| --- | --- |
| `0x05000F2C` | 启动路径选择 |
| `0x05001F5C` | MAIN 加载 |
| `0x050021B8` | BKUP 加载 |
| `0x050016E4` | MAIN 文件头标识及类型检查 |

在检查到 MAIN 加载错误的路径上，会尝试进入 BKUP。但这不证明文件头有效、运行后才死机的情况会自动恢复。强制备用启动的条件虽然已追到硬件输入，仍未确定实体入口和可重复操作流程。

因此项目不提供猜测的按键组合、不要求改坏 MAIN 触发备用启动，也不把其他型号的流程当作 GRD3 恢复方法。维修级恢复还缺少入口、写入范围、校准参数保护和实机复现证据。

## 本机备份的边界

研究时取得了校验通过的 MAIN、MONI、BKUP 和 EXTD 模块；整体 NAND 导出不完整，不是可直接写回整颗芯片的镜像。此前退出导出实验后恢复正常，也不等于固件刷坏后的恢复测试。

如要补充恢复能力，欢迎提交同型号、同版本的可核对资料和复现记录，明确区分正常回退、备用启动及故障恢复。
